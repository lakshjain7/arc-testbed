Per-service numbers: what the model sees for each box

These are the "node features" recorded for every service at B0, B1 and M in each episode. Same time window as the graph. A dash means no traffic reached that service in the window.

requests/min and errors: traces (OpenTelemetry agent → collector → Prometheus). p95: 95% of requests finished faster than this, from the same traces. It's estimated from time buckets, so treat it as approximate, and it's inflated by cold starts right after a restart. CPU, memory: the container runtime (cAdvisor). restarts, ready: Kubernetes (kube-state-metrics).

How to read it

calls succeeded in this window (moving = active)
at least one call on this edge failed
edge seen before, no calls in this window
Number on an edge = how many calls went along it in the chosen window. 12 / 1✗ = 12 succeeded, 1 failed.
Thicker edge = more calls. Red box = a caller saw errors from it. Dashed red box = pod not ready.
Edges appear ~10–20 s after a request (the collector waits to pair both ends of each call; Prometheus reads it every 5 s).
